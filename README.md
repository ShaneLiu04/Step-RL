> 面向自进化：能力门控发现未覆盖任务 → 真实 LLM 兜底成功一次 → 轨迹自动归纳为参数化技能 → 此后同类任务 **0 LLM**。  
> 移除任务：归纳前**未覆盖**，归纳后 **3/3**（跨商品/跨布局 + ID churn），0 prompt tokens；  
> **批量移除**：单条指令 2–3 商品，技能路径 **3/3**、0 LLM，单商品移除不回退。  
> **技能统计与优先级**：技能成败以验证器口径留痕，成功率下降即淘汰让位（0/1 → 显式缺口 → LLM 兜底 → 闭环重归纳），让位后同类任务 **0 LLM**。  
> **订单状态查询**：真实订单页 + 服务端状态谓词（有效/已取消），LLM 兜底 **1 步 / 186 tokens** 沉淀为 1 步技能，同类指令 **3/3、0 LLM**（含取消态迁移 + v2 布局 + ID churn）。  
> **优惠券约束规划**：满减券成为与预算同级的一等约束——对照真实券列表 + 实时价做可行性判定（不可行显式 None，不猜测不降级），服务端权威折扣结算，同类指令 **8/8 规划 + 3/3 执行、0 LLM**。  
> **并发会话隔离**：4 个真实 Edge 会话共享真实服务端并发执行，**4/4 成功且零串扰**（2.75× 并行），4 次真实 DOM 失败留痕 **4/4 精确**，10×12 并发写者 **0 损坏**。  
> **自适应观测缓存**：单往返快照 + DOM 修订号缓存，30 场景仍 **30/30、0 LLM**，观测往返 **−62.7%**、观测耗时 **−63.0%**。  
> **布局自适应技能编译**：v3 全新 DOM/控件（searchbox、查找、无 id、数量步进器）下，固定技能 **1/3** → LASC **3/3、0 LLM**，v1/v2 30/30 零回退。  
> **购物车事务编译**：所有商品加倍/统一改量/每件加一，baseline **0/3** → CTC **3/3、0 LLM**；真实更新故障下已改项回滚，**compensated=1**。  
> **购物车→订单事务**：加倍+满400减50+结算，baseline **0/3** → COT **3/3、0 LLM**；`total=1196/paid=1146`，券门槛不足时 0 动作，订单失败回滚 **compensated=2**。

## AR 价值总览：28 次尝试，27 次进入最优组合

我们不是先设计一个“大而全”的架构再寻找证据，而是让每次 AR 只回答一个真实失败：

> **失败发生在哪一层，就把那一层变成可执行、可验证、可回退的机制。**

28 次尝试中 **27 次进入最终组合**，1 次归档为负结果（AR002）；AR008 内部还回退了
“激进观测裁剪”，只保留干扰控件过滤。**负结果不是浪费**：它们排除了错误路线，
让最终组合没有被“看起来更多”的模块拖累。

|----------|----------|----------|------------------|

| 长链路后段丢失结构 | AR003/004/005 | E3 移除验证器观测 **100% → 33.3%**；L5 扁平失败、层级成功 | 证明层级与验证器观测是结构必需，不是提示词技巧 |

### 架构优越性：五个可验证结论

1. **可执行接地**：语义接口在 DOM churn 下仍是 100%，selector 在 0.75/1.0 时为 0%
   （EX002 E1）。
2. **长链路结构**：层级分解 9/9，扁平 8/9；移除验证器观测后 100% → 33.3%
   （EX002 E2/E3）。
3. **自进化闭环**：AR019–AR022 把未覆盖任务变成 0 LLM 技能复用，而不是永久依赖
   LLM 兜底。
4. **服务化可靠性**：AR024 在真实 4 并发会话下 4/4 零串扰、失败留痕 4/4、
   10×12 并发写者 0 损坏。
5. **端侧成本优势**：AR012 30/30、0 GPU、4 路并发约 2.73×；AR025 保持 30/30、
   0 LLM 的同时把观测往返降低 62.7%、观测耗时降低 63.0%。

### Agent + 端侧 LLM：组合而不是替代

| 层 | 真实证据 | 结论 |
|----|----------|------|
| 确定性 Agent/Runtime | 30/30、0 LLM、276 技能步、82.86s | 覆盖任务不调用模型 |
| 纯 LLM 本地执行 | 8/9（88.9%） | 能处理语义，但长链路退化 |
| 移除验证器观测 | 100% → 33.3% | LLM 不能替代权威验证 |
| 端侧 LLM 兜底 | remove 成功、4 policy steps、1142 tokens、28.17s | 未覆盖能力由模型补位 |

## 动机与目标

### 长链路 Web Agent 的三层失配

**1. 奖励失配：成功信号太稀疏**
真实任务只在最后给出成功/失败，中间大量“必要但无进展”的动作（输入数量、填写表单）得不到反馈。模型无法判断哪一步真正推进了任务。

**2. 技能失配：一个策略装不下多种能力**
数量控制、表单填写、多商品流程需要不同的行为分布。把它们塞进同一个策略，后训练的技能会覆盖先前的技能，造成长链路中断。

**3. 验证失配：成功不可执行验证**
如果“完成”由模型自己声明，训练信号就不可信。长链路任务必须有一个**外部、确定性、可执行**的成功判定。

### 本项目的目标

| 目标 | 设计回答 |
|------|----------|
| 成功可验证 | 可执行验证器 Φ，只读真实服务端状态 |
| 奖励可归因 | VGDP：步级 `ΔΦ` + 执行反馈 |
| 策略可优化 | Step-GRPO：任务分组 + token 级优势 |
| 技能可组合 | 层级任务分解 + 按子目标路由适配器 |
| 端侧可训练 | Qwen3-0.6B + LoRA，单卡 16GB |
| 实验可复现 | 真实浏览器 episode、JSON 产物、固定 seed |

### 运行时分层：每一层都由真实证据支撑

| 层 | 机制 | 支撑 AR | 真实证据 |
|----|------|---------|----------|

这张表是 README 的“架构主张”：**成功不是某个大模型的功劳，而是每层都有可执行、
可验证、可回退的机制。** 下面逐层说明。

### 1. 可执行验证器（Φ）

任务被写成有序谓词链：

```
search_done → product_viewed → cart_contains
→ cart_viewed → checkout_viewed
→ name_filled → address_filled → order_placed
```

`Φ = 已满足谓词 / 总谓词`。验证器只读真实 URL 与服务端状态，模型无法伪造。

### 2. VGDP 稠密奖励

```
r_t = 2.0·(Φ(s_{t+1}) − Φ(s_t))
    + 0.05·1[执行成功] − 0.10·1[执行失败]
    − 0.02 − 0.10·1[循环]
    + 1.0·1[终局成功] − 0.10·1[终局失败]
```

它把“输入数量 2”这类延迟收益动作，与随后真实的 `cart_contains` 变化关联起来。

### 3. Step-GRPO

- 同一任务采样 `G` 条轨迹，按任务分组；
- 回报 `G_t = Σ γ^{k−t} r_k`，组内标准化为步级优势；
- response token 继承所属步的优势；
- old log-prob 与采样分布一致，参考模型通过关闭 LoRA 获得。

### 4. 层级任务分解

长任务按验证器谓词链拆分：

```
「加 p3×1 + 加 p4×2 + 结算」
  → add p3      [SFT adapter]
  → add p4×2    [VGDP adapter]
  → checkout    [Sparse adapter]
```

- 同一真实浏览器会话，购物车状态不重置；
- 控制器只执行真实 `goto` 导航；
- 最终成功仍由**原任务验证器**判定。

### 5. 语义 Set-of-Mark 动作（DOM 改版鲁棒）

动作不再绑定 CSS id，而是引用当前观测中的元素编号：

```json
{"action": "click", "params": {"element": "e2"}}
```

- 观测为每个可交互元素分配 `e1/e2…`，并给出 `role + accessible_name`；
- 执行器通过 `data-eid` 在真实 DOM 中定位；
- 语义编号只在当前步有效，页面变化后重新生成；
- 语义模式下关闭 selector 修复，非法动作显式失败，不做静默兜底。

真实压力测试：观测后随机化全部 DOM id，selector 接口 L1–L2 成功率 0%，语义接口 100%。

### 6. 验证器感知观测 + DOM 接地修复

- Prompt 写入 `进度: 0.75 | 未完成: 填写收货人、提交订单`；
- selector 模式下，选择器失效时用真实 DOM 做唯一匹配修复；多候选一律放弃。

### 7. 失败驱动的技能自动归纳（AR019）

能力闭环的最后一环：兜底成功一次，永久转为 0-LLM 技能。

```
能力门控判缺口 (covered=false)
  → 真实 LLM 兜底执行一次（GPU + 真实浏览器）
  → TrajectoryRecorder 记录动作 + 语义元素元数据（执行前解析）
  → induce_skill 泛化为参数化模板（{product} / {qty}）
  → 注册技能库 + JSON 持久化 → 同类任务 0-LLM 直接执行
```

- 记录发生在**执行前**：eid 在当时观测中解析回 `role + accessible_name`，
  页面随后重渲染或 ID 扰动不丢失语义信息；
- 未注册的非 add 操作显式返回 `None`：能力缺口不得静默误路由到加购技能；
- 归纳技能与人工技能同标准：注册即过能力门控，30 场景统一套件回归检验；
- AR020 批量扩展：多目标规划解析 + 运行时「前缀一次 + 单元×N」展开 +
  块式轨迹归纳（最长公共后缀 unit），模板不随商品数漂移。

### 5.19 失败驱动的技能自动归纳（AR019）

**动机。** AR012 能力门控发现未覆盖任务后会拒绝执行或回退 LLM，但兜底成功的
轨迹此前被直接丢弃——同类任务下次仍要重新付出一次 LLM 成本。能力闭环
缺了最后一环：**把兜底成功经验自动沉淀为可复用技能**。此前所有技能
（AR010/AR015）都来自真实专家演示的人工参数化；AR019 把
「成功轨迹 → 参数化技能」这一步自动化：任何能力缺口，只要 LLM 兜底
成功一次，运行时自行完成沉淀，无需专家在场。

### 5.23 优惠券约束规划（AR023）

**动机。** AR006 把自然语言约束（预算/最便宜/最贵/缺货替代）编译为

执行，`outputs/ar023/baseline_probe.json`）暴露三层缺口：

1. **规划器静默丢约束**：8 条优惠券指令全部编译出无促销约束的 spec，

   无结算动作）也照常编译成看似成功的计划——**约束被丢弃、成功被
   保留**，属于不可接受的静默降级；
2. **站点无促销支撑**：真实 `GET /api/promos` → 404，v1/v2 结算页无
   领取元素，订单 JSON 无 `total/paid/promo` 字段——服务端无法权威确认

3. **验证器无促销谓词**：`order_promo_applied` 不存在，即使订单带折扣，
   成功判定也读不到。

目标（BACKLOG B05）：满减券成为与预算同级的**一等约束**——对照
**真实券列表**（`/api/promos`）与**实时目录价**做确定性可行性判定
（可行 → `require_promo` + 真实促销码；不可行 → 显式 `None`，不猜测
不降级）；站点提供真实**无导航领取**交互；服务端在下单时权威结算
折扣（`total/paid/promo.applied`）；验证器只读服务端订单字段；编译
结算技能增量一步「领取…」，全程 **0 LLM**。

**机制（与前序 AR 的对照）。**

| 环节 | AR006（预算约束） | AR023（券约束） |
|------|------|------|
| 约束表达 | spec 内 `budget` 数值 | `require_promo` + 促销码（来自真实 `/api/promos`） |
| 可行性判定 | 超预算 → 删最贵行或 None | 总额<门槛 / 券面不存在 / 无结算 / 无真实列表 / 仅泛称「优惠券」→ **显式 None**（4 组指令回归守卫） |
| 执行支撑 | 既有技能 | 编译结算技能在「提交订单」前插入一步 `click button「领取{券面}优惠」`（无码路径与旧 4 步逐字段一致，单测固化） |
| 成功判定 | `order_placed` 等 | `order_promo_applied`：只读服务端 `order.promo.applied ∧ code` |

### 5.24 并发会话隔离（AR024）

**动机。** AR011–AR023 的评测均是单会话串行：一个进程一个 `BrowserEnv`、
一个任务。端侧运行时若以多会话方式服务（同进程多个真实 Edge 会话并发），
进程内共享的**技能运行时组件**就成为串扰面。改动前基线探针（旧代码真实
执行，`outputs/ar024/baseline_probe.json`）实测四处缺口：

1. **统计读改写非原子**：`skill_stats._STATS` 的 `attempts/successes/failures`
   并发更新可能互相吞掉；
2. **跨会话重载擦除**：`from_dict` 的 `clear()` + 逐项插入不是原子替换，
   并发「记录 + 重载」可抹掉另一会话留痕，并暴露半完成中间态；
3. **持久化非原子**：并发 `save_skill_stats` 直写同一文件，探针中
   **10/10 轮出现混合快照**、**10/10 轮工作线程因
   `dictionary changed size during iteration` 崩溃**；
4. **注册表 upsert 竞态**：`register_induced_skill` 先查后追加，
   4 路同名并发注册产生 **2 个重复候选**，干扰 AR021 的成功率选择。

服务端 `SessionStore` 自带锁且按 `sid` 键控：探针 E4 用 2 个真实并发
Edge 会话验证**服务端层零串扰**，因此改动面严格限定在进程共享的
技能运行时层。

**机制（标准库 only，不改既有签名与 JSON 形状）。**

| 组件 | 加固 |
|------|------|
| `skill_stats.py` | 模块级 `threading.Lock`；`record_skill_outcome` 全临界区；`from_dict` 原子替换；保存取一致快照 |
| `skill_library.py` | 模块级锁；`register_induced_skill` 的「查重 + 替换/追加」原子化；保存取一致快照 |
| `concurrency.py` | `atomic_write_json`（同目录临时文件 + `os.replace`，Windows 重试）；`run_concurrent`（每会话一线程一事件循环，异常按槽位隔离，返回墙钟） |

关键决策：锁内只做内存读写/快照构建，**I/O 一律锁外原子写**；
`load` 语义为「完整解析后原子替换（后到者胜）」，不跨调用方合并；
保留 `list + 锁内查重` 的多候选语义（AR021 逐字段零漂移）。

**真实评测（P0–P4，真实 Edge / 共享真实服务端 / 0 LLM）。**

| 阶段 | 内容 | 结果 |
|------|------|------|
| P0 | 锁/原子写导入断言 + 单会话串行对照 | ✓ 0 LLM，`p3×2`，2.2s |
| P1 | 4 个真实 Edge 会话并发（不同任务，barrier 起跑） | **4/4 成功，零串扰**；墙钟 3.74s vs 逐会话和 5.80s（**2.75×**）；逐会话服务端快照精确等于自身任务 |
| P2 | 4 会话并发真实 DOM 失败（注入错误模板） | **失败 4/4、统计 attempts=4 / failures=4**，淘汰门控翻转，审计 JSON 可解析 |
| P3 | 10 轮 × 12 并发写者（统计 + 技能注册表） | **损坏 0、混合快照 0、死写者 0** |
| P4 | 串行回归：购买两件 + 数量改为 3 | 均成功，**0 LLM**，1.34s / 0.70s |

### 5.25 自适应观测缓存（AR025）

**动机。** AR011–AR024 每次动作后都调用 `BrowserEnv.observe()`；旧实现一次
observe 触发 **4 次浏览器往返**（元素扫描、body 文本、`/api/state`、title），
技能层还存在“末次已观测、返回后再观测”的冗余。真实基线探针
（`scripts/ar025_baseline_probe.py`，AR011 30 场景、真实 Edge、0 LLM）：

- observe **440 次**、耗时 **10.96s**、浏览器往返 **1760 次**；
- 相邻快照完全一致 **166 次（37.7%）**。

目标（BACKLOG B08）：不改变动作/技能/验证器语义，把观测层改为
**单往返快照 + DOM 修订号缓存**；服务端 state 永不缓存，保证验证器权威性。

**机制。**

| 组件 | 改动 |
|------|------|
| `browser.py` | init script 注入 MutationObserver（忽略 `data-eid` 自身写入），维护 `rev/doc`；`_META_JS` 一次返回 rev/doc/url/title + 实时 `/api/state`；`_OBSERVE_JS` 一次返回元素表 + body 文本 |
| 缓存 | 键 `(doc, url, rev, title)`；命中复用元素/文本、仅刷新 state；`type` 动作主动失效（value property 不触发 mutation）；导航/换页 doc 变化必失效 |
| `skill_library.py` | `run_skill(initial_obs=...)` 复用调用方观测；返回末次观测；`run_skill_hierarchy` 删除技能后重复 observe，并用其作为 LLM fallback 初始观测 |

**真实评测（30 场景 / 真实 Edge / 0 LLM）。**

| 指标 | 基线 | AR025 | 变化 |
|------|------|-------|------|
| 成功率 | 30/30 | **30/30** | 不回退 |
| LLM 步 / Prompt tokens | 0 / 0 | **0 / 0** | 不回退 |
| observe 调用 | 440 | **328** | −25.5% |
| 浏览器往返 | 1760 | **656** | **−62.7%** |
| observe 耗时 | 10.96s | **4.06s** | **−63.0%** |
| 总墙钟 | 81.65s | **76.71s** | −6.0% |

独立真实缓存探针（重复 observe + wait）：**4 次调用、3 命中、1 扫描**，
元素稳定且 state 实时。技能路径每个动作都真实改变 DOM，因此 30 场景

## 训练算法

### SFT

- Qwen3-0.6B-Base + LoRA（`r=16, alpha=32, all-linear`）
- response-only 损失，prompt token 被 mask
- 真实专家轨迹，只覆盖 L1–L2

### Step-GRPO

```
G_t = Σ_{k=t}^T γ^{k−t} r_k
A_t = (G_t − mean_group) / (std_group + ε)
ratio = exp(logπ_new − logπ_old)
L = −min(ratio·A_t, clip(ratio,1−ε,1+ε)·A_t) + β·k3(π_ref, π_new)
```

`γ=0.95, ε=0.2, β=0.02`，损失只作用于 response token。

## 常见问题

<details>
<summary><b>Q1：为什么需要层级分解，而不是一个更大的模型？</b></summary>

层级分解解决的是**技能干扰与信用边界**，不是容量问题。把“数量控制/结算/多商品”拆到不同适配器后，每个子目标都在其训练分布内执行，端侧 0.6B 也能稳定完成长链路。
</details>

<details>
<summary><b>Q2：专家前缀是否影响公平性？</b></summary>

L4/L5 的 Step-GRPO 训练使用相同专家前缀到达结算页；Sparse 与 VGDP 完全一致，差异只来自奖励。最终 AR004 评测**不使用前缀**。
</details>

<details>
<summary><b>Q3：为什么有 AR002 负结果？</b></summary>

记忆 prompt 干扰小模型、重规划触发不足、LoRA 权重融合破坏能力。项目按“组合必须综合更优”原则回退，并保留负结果供后续研究。
</details>

<details>
<summary><b>Q4：只有一张小显卡能跑吗？</b></summary>

可以。端侧 pilot 使用 Qwen3-0.6B + LoRA，16GB 足够；7B 建议 A100 40GB。
</details>

<details>
<summary><b>Q5：语义动作如何保证不点错元素？</b></summary>

`eid` 只在当前观测快照内有效，执行器只接受本步生成的 `data-eid`；无效编号会显式失败，不做静默兜底。语义模式下关闭 selector 修复，避免掩盖错误。
</details>

<details>
<summary><b>Q6：如何扩展到公网网站？</b></summary>

替换 `BrowserEnv` 的服务端与 `TaskSpec`/验证器；语义接口可直接用于真实站点，但需注意 URL 白名单、登录态与安全沙箱。建议先在本地站点验证，再逐步放开域名。
</details>
