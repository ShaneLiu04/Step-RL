## 1. 背景与目标

AR001 的单一策略在 9 个留出任务上达到 77.8%，但两类长链路任务仍失败：

- L4：数量 2 + 结算；
- L5：多商品结算。

根因不是模型不会单步技能，而是**多种技能在一个策略里相互干扰**：数量控制需要 VGDP 适配器，结算流程需要 Sparse/SFT 适配器；单模型路由按任务选择了其中一个，导致另一段技能退化。

本 AR 将长链路任务按验证器谓词链拆分为**有序子目标**，每个子目标调用该技能最优的适配器，同时保持同一个真实浏览器会话与购物车状态。

目标：在真实留出任务上达到 **100% 成功率**，并严格优于 AR001 的 77.8%；若未达到则回退。

## 2. 需求范围

**In Scope：**

- `decompose_task()`：将 checkout/multi 任务拆为“加商品 A → 加商品 B → 结算”。
- `adapter_for_subtask()`：子目标到适配器的路由。
- `run_hierarchy()`：共享会话的顺序执行器，含真实控制器导航。
- 多适配器同基座加载（`load_multi_adapter`），运行时切换，不重复加载模型。
- 真实评测脚本 `scripts/ar003_eval.py`。
- 单测：分解、路由、导航/成功判定。
- README 重构：以动机、目标、架构为中心，移除历史兼容叙述。

**Out of Scope：**

- 新增 RL 训练。
- 新环境/新商品。
- 公网站点。

## 3. 功能需求

### FR1 任务分解

**描述：** 根据 `require_checkout` 与 `targets` 生成子任务。

**验收：**
- Given 单商品结算任务，Then 生成 `[add_item, checkout]`。
- Given 多商品任务 p3×1+p4×2，Then 生成 `[add_p3, add_p4, checkout]`，且顺序与 targets 一致。
- 非结算任务原样返回。

### FR2 子目标适配器路由

**描述：** 每个子目标选择最合适的适配器。

**规则：**
- 结算子目标 → `checkout`（Sparse）；
- 数量 ≥2 的加购 → `quantity`（VGDP）；
- 其他加购 → `base`（SFT）。

**验收：** 三个子目标分别命中 `base/quantity/checkout`。

### FR3 共享会话执行

**描述：** 子目标之间不 reset 浏览器；控制器只做真实 `goto` 导航。

**行为：**
- 第一个子目标从任务起始页开始；
- 后续加购子目标导航到 `/`；
- 结算子目标导航到 `/checkout`；
- 每个子目标最多 8 步。

**验收：**
- Given 多商品任务，Then 购物车在子目标间保留已加商品。
- 控制器导航记录 `source=controller`，不伪造成功。

### FR4 多适配器加载

**描述：** 一个基座模型加载多个 LoRA adapter，运行时 `set_adapter` 切换。

**验收：**
- 显存不随子任务数线性增长（仅一份基座）。
- 切换后生成行为与单独加载该 adapter 一致。

### FR5 最终成功判定

**描述：** 最终成功由原任务验证器判定，而不是子目标成功之和。

**验收：**
- Given 所有子目标成功但购物车/订单不满足原任务，Then 判定失败。
- Given 原任务谓词全部满足，Then 成功。

### FR6 真实评测

**描述：** 在 9 个留出任务上执行 greedy 评测，输出 JSON。

**验收：**
- 成功率、平均步数、平均 Φ、控制器动作数、子目标数全部落盘。
- 若成功率 ≤77.8%，回退 AR001 路由方案。

## 4. 非功能需求

| 类型 | 要求 |
|------|------|
| 训练成本 | 0 新增训练 |
| 评测时间 | 9 任务 ≤ 10 分钟（本机限频） |
| 显存 | 单份 0.6B 基座 + 3 个 LoRA |
| 可复现 | 固定 seed、greedy、JSON 产物 |
| 安全 | 所有动作仍经白名单与 DOM 校验 |

## 5. 约束与假设

- 任务可分解为“逐商品加购 + 结算”的结构。
- 部署时已知任务类型（是否结算、目标商品与数量）。
- 子目标适配器均来自同一 SFT 基座，兼容同一 tokenizer/格式。

## 6. 术语

| 术语 | 定义 |
|------|------|
| 子目标 | 由验证器谓词定义的可独立完成阶段 |
| 控制器 | 子目标之间执行真实导航的执行器 |
| 多适配器 | 同一基座上按名称切换的 LoRA |
