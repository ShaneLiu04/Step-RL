## 1. 背景与目标

EX001/E8：端侧瓶颈是 LLM 生成（8.3s/步），但大量动作是稳定、可复用的技能（搜索、加购、结算）。AR010 将真实成功轨迹中的动作模式编译为参数化技能，技能执行不调用 LLM；失败时回退到 LLM。

目标：9 个留出任务成功率 100%，LLM 调用与 prompt tokens 显著下降；失败则回退。

## 2. 范围

**In：**
- 参数化技能库：`search(query)`、`add_item(pid,qty)`、`checkout()`；
- 技能执行器（真实浏览器 + 语义元素）；
- 技能失败回退 LLM；
- 9 任务 baseline vs skill 真实评测；
- v2 + ID churn 技能迁移；
- 单测、报告、README、复现文档。

**Out：**
- 自动程序归纳算法（本轮技能由真实轨迹模式参数化）；
- 新模型训练；
- 公网站点。

## 3. 功能需求

### FR1 技能库

- 搜索：goto `/` → 输入查询 → 点击搜索；
- 加购：goto `/` → 搜索 → 打开商品 → 设置数量 → 加购；
- 结算：goto `/checkout` → 填收货人/地址 → 提交。

元素通过 `role/accessible_name` 在真实 DOM 中解析，不依赖 CSS id。

### FR2 技能执行

- 每步真实执行；
- 任一步失败/元素缺失 → 技能失败；
- 记录 `source=skill`，不产生 prompt/gen token。

### FR3 回退

- 技能失败时，用当前观测调用 LLM 子任务；
- 最终成功由原验证器判定。

### FR4 评测

| 条件 | 执行 | 环境 |
|------|------|------|
| baseline | LLM 层级 | v1 |
| skill | 技能优先 + 回退 | v1 |
| skill_churn | 技能优先 + 回退 | v2 + id churn |

指标：成功率、步数、LLM 调用数、prompt tokens、耗时。
验收：成功 100%；LLM 调用显著下降（目标 ≥50%）；否则回退。

## 4. 非功能

| 类型 | 要求 |
|------|------|
| 训练成本 | 0 |
| 技能额外延迟 | <1ms/步（解析除外） |
| 可复现 | 固定 seed、JSON |
| 安全 | 仍走动作白名单与真实 DOM |

## 5. 假设

- 任务可分解为稳定子目标；
- 语义名在布局变化下保持；
- 技能覆盖常见子目标，失败可回退。

## 6. 术语

| 术语 | 定义 |
|------|------|
| 技能编译 | 将成功轨迹动作模式参数化为可执行技能 |
| 免生成执行 | 技能执行不调用 LLM |
| 回退 | 技能失败后交给 LLM |
