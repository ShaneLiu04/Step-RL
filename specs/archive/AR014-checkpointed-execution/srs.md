## 1. 背景与目标

真实 Agent 会因浏览器/进程崩溃中断。当前技能执行没有持久化检查点，崩溃后只能从头执行；对“买 2 件”的任务会重复加购成 4 件，而现有 `>=` 验证器会把多买误判为成功。

AR014 增加：

- 浏览器 `storage_state` 保存/恢复（真实会话 cookie）；
- 技能执行检查点；
- 精确数量验证器（`==`）；
- 崩溃恢复 vs 从头执行真实对照。

目标：恢复 3/3，基线 0/3；否则回退。

## 2. 范围

**In：**
- `TaskSpec.exact_quantity` 与验证器；
- BrowserEnv 保存/恢复 storage_state；
- 崩溃恢复评测 3 个任务；
- 单测、报告、README、复现文档。

**Out：**
- 任意进程崩溃；
- 多机持久化；
- 公网。

## 3. 功能需求

### FR1 精确数量

- `exact_quantity=True` 时购物车/订单数量必须等于目标；
- 默认仍为 `>=`，不影响既有任务。

### FR2 会话保存

- 保存 Playwright `storage_state`（cookie/session）；
- 新上下文可加载该状态，服务端会话保持。

### FR3 崩溃恢复

- env1 完成加购技能后保存状态并关闭；
- env2 加载状态，继续结算技能；
- 最终订单数量精确等于目标。

### FR4 基线

- env1 完成加购后关闭但不保存；
- env2 从头执行完整任务；
- 加购重复，精确验证失败。

### FR5 评测

| 任务 | 目标 |
|------|------|
| p4×2 结算 | 2 |
| p3×2 结算 | 2 |
| p1×1+p2×1 结算 | 1/1 |

- 恢复 3/3，基线 0/3；
- 记录订单数量与耗时。

## 4. 非功能

| 类型 | 要求 |
|------|------|
| 训练成本 | 0 |
| 恢复时间 | <5s |
| 可复现 | 固定 seed、JSON |
| 安全 | 仍走真实 DOM/动作白名单 |

## 5. 假设

- 服务端会话由 cookie 标识；
- storage_state 可跨上下文恢复；
- 崩溃注入为真实浏览器关闭/重开。

## 6. 术语

| 术语 | 定义 |
|------|------|
| storage_state | Playwright 保存的 cookie/localStorage |
| 检查点 | 完成部分子目标后的可恢复状态 |
| 精确数量 | 订单数量必须等于目标 |
