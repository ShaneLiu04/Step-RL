## 1. 背景与目标

AR005 已能在未见布局与重渲染下 100% 执行，但输入仍是外部构造好的 `TaskSpec`。真实用户只给一句话，例如：

- “买最便宜的商品并结算”
- “预算 300 元内买最贵的”
- “无线充电器缺货就买蓝牙耳机”
- “买一件 iPhone 和两件数据线”

系统需要从自然语言中理解商品、数量、预算、最值、缺货替代，并编译成验证器可执行的任务规格。

目标：在同一批真实指令上，约束规划器显著优于关键词基线，并在跨布局 + 重渲染下仍能执行成功。

## 2. 需求范围

**In Scope：**

- 真实商品目录 API 增加库存字段；
- 库存真实校验（加购超库存失败）；
- `planner.py`：约束解析与 `TaskSpec` 编译；
- 关键词基线 `naive_plan`；
- 真实评测：规划准确率 + 按用户期望的执行成功率；
- 单测、README、复现手册、封面。

**Out of Scope：**

- 大模型微调解析器；
- 新商品/新页面；
- 公网站点。

## 3. 功能需求

### FR1 库存

**描述：** `/api/products` 返回实时库存；`/add` 超库存返回错误。

**验收：**
- stock=0 的商品无法加购；
- 加购数量累计不超过库存。

### FR2 约束解析

**描述：** 从指令识别商品、数量、预算、最值、缺货替代、结算意图。

**验收：**
- “最便宜” → 最低价在库商品；
- “不超过 300 元的最贵” → 预算内最高价；
- “两件 USB-C 数据线” → p2×2；
- “iPhone + 两件数据线” → p1×1 + p2×2；
- “无线充电器缺货就买蓝牙耳机” → 在库替代品；
- “三件蓝牙耳机” → p4×3。

### FR3 任务规格编译

**描述：** 输出 `TaskSpec`，包含 targets、数量、结算意图、搜索关键词。

**验收：**
- 生成的 TaskSpec 可直接交给 AR003/AR005 层级执行器；
- 每个 target 在库、数量合法。

### FR4 基线对照

**描述：** 关键词基线只匹配第一个商品、数量默认 1，不处理预算/最值/缺货/多商品。

**验收：**
- 同一批指令，基线规划准确率显著低于规划器；
- 执行成功按**用户期望 TaskSpec**判定，而不是按各自规划结果自证。

### FR5 真实评测

**描述：** 8 条指令，三种条件：基线 v1、规划器 v1、规划器 v2+churn。

**验收：**
- 规划器规划准确率 100%；
- 规划器按期望执行成功率 100%；
- 基线按期望成功率接近 0（允许偶然执行成功但规划错误）；
- 逐条结果落盘。

### FR6 回退

**描述：** 若规划器低于 AR005 的 100%，回退。

**验收：**
- 回退时保留 AR005 并记录负结果。

## 4. 非功能需求

| 类型 | 要求 |
|------|------|
| 训练成本 | 0 新增训练 |
| 规划延迟 | 单指令 <50ms（规则求解） |
| 可复现 | 固定目录/库存、JSON 产物 |
| 安全 | 生成目标必须通过库存与动作白名单 |

## 5. 约束与假设

- 商品目录可由 `/api/products` 实时读取；
- 指令为中文，包含明确或隐含约束；
- 预算/最值/替代规则可确定性求解。

## 6. 术语

| 术语 | 定义 |
|------|------|
| 任务编译 | 自然语言 → TaskSpec |
| 期望规格 | 用户真实期望的 targets，用于判定成功 |
| 规划准确率 | 编译出的 targets 是否等于期望 |
| 关键词基线 | 只匹配第一个商品、数量 1 的解析器 |
