| AR 主题 | observation-pruning |
| 关联 SR | 端侧 token/延迟优化的验证器引导观测压缩 |
| 日期 | 2026-11-04 |

## 1. 背景与目标

EX001 的 E7/E8 显示：
- 每成功任务 prompt tokens 为 1429（L3）–3667（L5）；
- GPU 单步生成 8.3s，显存仅 1.28GB。

端侧瓶颈是输入/生成，而非显存。AR008 在不改变动作格式、不重训模型的前提下，按验证器缺失谓词与页面语义裁剪观测元素，移除真实干扰控件（排序/筛选/收藏/返回/继续购物），保留可推进任务的元素。

目标：9 个留出任务成功率保持 100%，prompt tokens 显著下降；否则回退。

## 2. 范围

**In：**
- `prune_elements(elements, task, missing)` 相关性评分；
- rollout/hierarchy 可选 `observation_pruning`；
- 9 任务 full vs pruned 真实对比（成功、步数、tokens、延迟）；
- 单测、报告、README、复现文档。

**Out：**
- 重训模型；
- 视觉截图压缩；
- 新任务/新布局。

## 3. 功能需求

### FR1 相关性评分

**描述：** 根据缺失谓词与元素语义名打分。

- search_done：搜索框/搜索按钮；
- product_viewed/cart_contains：商品名/关键词/加入购物车/数量；
- checkout_viewed：去结算；
- name/address/order：收货人/地址/提交订单；
- 干扰项：排序/筛选/收藏/返回/继续购物 → 负分；
- 保留少量导航元素。

### FR2 裁剪

**描述：** 保留得分最高的 K 个元素（K=6），保持原顺序。

**验收：**
- 至少保留所有直接匹配缺失谓词的元素；
- 不改变 `eid/role/accessible_name` 字段结构；
- 无匹配时回退到原列表前 K 个。

### FR3 执行集成

**描述：** `observation_pruning=True` 时，每步观测先裁剪再构造 prompt。

**验收：**
- 动作执行仍作用于真实 DOM；
- 验证器、控制器、层级逻辑不变。

### FR4 真实评测

**描述：** 9 个留出任务，full vs pruned。

**验收：**
- 成功率均为 100%；
- prompt tokens 下降 ≥30%；
- 若成功率下降，保留 full 并记录回退。

## 4. 非功能需求

| 类型 | 要求 |
|------|------|
| 训练成本 | 0 |
| 额外延迟 | 裁剪 <1ms |
| 可复现 | 固定 seed、JSON |
| 安全 | eid 仍由真实 DOM 生成 |

## 5. 约束与假设

- 当前适配器在完整观测上训练；裁剪是推理期特征选择，存在分布偏移；
- 只在语义接口上评测；
- K=6 为初始值，不做逐任务调参。

## 6. 术语

| 术语 | 定义 |
|------|------|
| 观测压缩 | 仅保留与缺失谓词相关的元素 |
| 干扰控件 | 不推进任务的真实页面按钮 |
| prompt tokens | 策略输入 token 数 |
