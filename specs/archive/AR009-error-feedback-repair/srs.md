## 1. 背景与目标

当前策略只看到 `ok/fail`，看不到服务器/表单的**错误原因**。真实表单会因“收货人需包含称谓”“地址需包含路”等校验拒绝订单；模型只能重复原动作。

AR009 增加错误可观测与闭环修复：

1. 观测中暴露真实错误文本；
2. 策略可据此纠正；
3. 未纠正时，控制器按错误语义执行一次真实字段修复；
4. 成功仍由原验证器判定。

目标：在 2 个真实表单校验任务上，基线 0/2，本方案 2/2；若不能提升则回退。

## 2. 范围

**In：**
- 服务器表单校验（收货人称谓、地址含“路”）与错误页；
- 观测中的错误提示；
- 错误语义→字段修复控制器；
- 基线/仅可观测/可观测+修复 三组真实评测；
- 单测、README、复现文档。

**Out：**
- 任意错误类型；
- 新模型训练；
- 公网站点。

## 3. 功能需求

### FR1 表单校验

- 收货人必须包含“先生/女士”；
- 地址必须包含“路”；
- 失败返回明确错误文本，不生成订单。

### FR2 错误可观测

- 观测/提示中包含页面错误文本；
- 仅在错误出现时注入，避免常态 token 膨胀。

### FR3 控制器修复

- 错误含“称谓” → 用“刘星言先生”重填收货人；
- 错误含“路” → 用“深圳市龙岗区坂田路1号”重填地址；
- 每次修复都真实执行并记录 `source=error_repair`。

### FR4 评测

| 条件 | 错误提示 | 控制器修复 |
|------|----------|------------|
| baseline | ✗ | ✗ |
| observable | ✓ | ✗ |
| observable+repair | ✓ | ✓ |

- 2 个任务，按用户期望验证成功；
- 基线 0/2，组合 2/2 才保留。

## 4. 非功能

| 类型 | 要求 |
|------|------|
| 训练成本 | 0 |
| 额外 token | 仅错误时注入 |
| 可复现 | 固定 seed、JSON |
| 安全 | 修复仍走真实 DOM 与动作白名单 |

## 5. 假设

- 错误文本可由页面真实读取；
- 控制器修复是通用错误→字段映射，不是任务硬编码。

## 6. 术语

| 术语 | 定义 |
|------|------|
| 错误可观测 | 策略能看到真实错误原因 |
| 字段修复 | 按错误语义重填表单 |
| 期望判定 | 用用户期望 TaskSpec 验证成功 |
