## 1. 背景与目标

真实服务偶发瞬时错误（500/超时）。当前技能执行一次失败即结束或回退，不对瞬时故障重试。

AR018 增加：

- 服务端一次性 `/add` 或 `/place-order` HTTP 500；
- 运行时同 TaskSpec 技能重试一次；
- 基线一次执行 vs 重试对照；
- 不加载模型、纯 CPU。

目标：重试 3/3，基线 0/3；否则回退。

## 2. 范围

**In：**
- 服务端瞬时故障注入（每会话一次）；
- runtime `skill_retries`；
- 3 个故障任务评测；
- 单测、报告、README、复现文档。

**Out：**
- 网络层重试；
- 新模型训练；
- 公网。

## 3. 功能需求

### FR1 故障注入

- `fault_add_once`：首次 `/add` 返回 500；
- `fault_order_once`：首次 `/place-order` 返回 500；
- 每会话只触发一次，重置后重新计数。

### FR2 重试

- `run_task(..., skill_retries=1)`；
- 技能失败且重试预算 >0 时，同 TaskSpec 再执行一次；
- 每次重试 reset 真实会话。

### FR3 评测

| 任务 | 故障 |
|------|------|
| F1 p3×1 结算 | add 500 |
| F2 p4×2 结算 | add 500 |
| F3 p2×1 结算 | order 500 |

- baseline：`run_skill_hierarchy` 一次；
- runtime：`run_task` 重试；
- 成功由验证器判定。

## 4. 非功能

| 类型 | 要求 |
|------|------|
| 训练成本 | 0 |
| 重试耗时 | <5s |
| 可复现 | 固定 seed、JSON |
| 安全 | 真实 DOM/动作白名单 |

## 5. 假设

- 故障是瞬时且每会话一次；
- reset 会清除故障计数；
- 重试不会重复成功订单（失败时无订单）。

## 6. 术语

| 术语 | 定义 |
|------|------|
| 瞬时故障 | 一次性 500，重试可恢复 |
| 技能重试 | 同 TaskSpec 重新执行技能 |
