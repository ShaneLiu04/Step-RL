# [EX002] 实验设计

## 1. 思路

不新增架构，只用真实执行对现有组合做压力归因：

- **E1–E3 重跑**：当前 AR026 代码下的核心设计归因，防止旧报告与代码漂移；
- **E4–E8 组合压力**：布局异构、观测开销、并发、故障长链路、统一运行时；
- **覆盖矩阵**：把每个 AR 映射到至少一个真实证据，负结果显式保留。

## 2. 数据流

```
ex001_e1/e2/e3.py ──> outputs/ex001/*.json
ar011/012/016-18/024-026 ──> outputs/ar*/...
        └──> scripts/ex002_summary.py ──> outputs/ex002/summary.json
                    └──> scripts/ex002_figures.py ──> docs/results/figures/ex002/*.png
                    └──> docs/results/EX002_report.md
```

## 3. 实验决策

- **D1 同站点双向对照**：E1/E2/E3 使用同一真实站点与模型；E4 的 v3 baseline
  与 LASC 使用同一 v3 站点，只关闭自适应，避免伪造对照。
- **D2 指标口径**：成功以验证器/服务端状态为准；观测/并发指标来自运行时代码
  计数，不手工填数。
- **D3 负结果保留**：AR002 与 AR008 激进裁剪不进入最优组合；EX002 明确记录。
- **D4 边界透明**：E1 小样本、E3 推理期消融、AR024 单进程边界写入威胁节。

## 4. 测试与复现

E1–E3 沿用 EX001 真实脚本；E4–E8 复用 AR 评测脚本；汇总/绘图为
`ex002_summary.py`/`ex002_figures.py`。完整命令见
`docs/EXPERIMENTS_EX002.md`。

## 5. 回滚

实验不修改运行时；若 E1–E3 与当前代码不一致，则修正报告或代码后再归档。
