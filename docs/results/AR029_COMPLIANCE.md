# AR029 合规与安全说明（JD dry-run）

## 1. 授权范围

- 仅使用用户本人提供的 JD 测试账号；
- 仅运行用户授权的低价值 3C 配件任务；
- 单笔金额上限 **≤200 元**；
- 不访问非公开数据、不抓取用户隐私、不规避平台 ToS。

## 2. 支付与下单

- AR029 **默认 dry-run**：不点击提交订单、不自动支付；
- 到达结算页即停止，验证金额/商品/券信号；
- 真实提交/取消不在 AR029 范围，留到有人值守的后续 AR；
- 代码中 `submit_order` 显式抛出 `PermissionError`，不存在静默提交路径。

## 3. 频率与并发

- 单会话；
- 动作间隔 **≥5 秒**；
- 每次 run **≤20 个页面**；
- 命中登录/验证码/风控 → 暂停并转人工，不绕过。

## 4. 凭据与数据

- 登录态存放：`%LOCALAPPDATA%\StepRL\credentials\jd.json`（不入仓）；
- 证据目录：`outputs/ar029/jd/<run_id>/`（已被 .gitignore 忽略）；
- JSONL/HTML 写入前对 password/cookie/token/authorization 脱敏；
- 日志不记录账号密码、支付信息；截图最小化。

## 5. 真实性与失败

- 所有 JD 结果必须来自真实 Edge/真实页面；
- 至少 1 个真实失败/拒绝案例：不可行券、无结果搜索、库存不足；
- 不允许用静态 HTML 冒充真实运行；页面快照必须带 run_id 与 URL；
- 若无法登录/风控命中，记录为“待人工/拒绝”，不得伪造成功。

## 6. 审批

- 真实 JD 实验前需用户现场接管登录/验证码；
- 任何金额、账号、频率变更需用户确认；
- AR029 不包含自动支付与批量抢购。
